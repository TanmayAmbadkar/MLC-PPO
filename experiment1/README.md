# Experiment 1: frozen-policy value prediction

`collect.py` samples two trajectories per GSM8K problem, saves activations from layers at 50%, 75%, and 100% depth at three response prefixes, and samples independent continuations from each prefix. It saves individual binary outcomes as well as the features. Splits are made by question before generation. The frozen model and sampling configuration are recorded in `config.json`; reruns resume at completed problem files and reject mismatched configurations.

The defaults use Qwen2.5-Math-1.5B-Instruct, 200/50/50 train/validation/test problems and 8/16/32 continuations per state. Sampling uses temperature 0.8 and top-p 0.95. Continuations share the original response token budget; an incomplete response at the limit is scored using the same answer extractor. Very short trajectories are skipped and recorded in the log, so actual state counts may be lower than the intended counts.

`fit.py` trains a final-layer head, final-layer ensemble, multi-layer ensemble, and a larger parameter-matched final-layer head. It evaluates the multi-layer ensemble's mean, minimum, and a gate trained on separate training problems. Validation selects training epochs; the test set is used only for reporting. `metrics.json` contains value MSE, per-outcome Brier score, problem-level bootstrap intervals, paired C-versus-B MSE difference, error by prefix progress and descriptive problem success group, head parameter counts, and head forward timings. A progress plot is written when matplotlib is installed. These timings cover critic heads only, not the cost of retaining intermediate activations.

Submit the complete experiment from the repository root with `qsub pbs_experiment1.sh`. It may require a long GPU allocation. A smaller smoke run can use `qsub -v DATA_DIR=runs/experiment1_smoke/data,RESULTS_DIR=runs/experiment1_smoke/results,TRAIN_PROBLEMS=3,VAL_PROBLEMS=1,TEST_PROBLEMS=1,MAX_NEW_TOKENS=64 pbs_experiment1.sh`. Smoke results are only for checking the pipeline. No PPO training is involved.

For four separate one-GPU jobs, submit `pbs_experiment1_worker.sh` four times with ranks 0 through 3 and the same fresh `MARKER_DIR`. Stop any other collector using the data directory first. Each worker handles a disjoint quarter of each split and resumes completed problem files. Worker 0 runs fitting after all four workers finish successfully.
