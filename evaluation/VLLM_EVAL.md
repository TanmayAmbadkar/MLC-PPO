# Batched vLLM evaluation

The stage evaluations in `pbs_fast2_eval.sh` run `evaluation/viability_vllm.py`, using vLLM 0.17.1 in the isolated vLLM environment. It uses the pinned MATH-500 and AIME 2024 dataset revisions, original Qwen tokenizer, same chat prompt and math verifier, greedy decoding, FP32 model weights, 2,048-token limit, explicit trainer EOS, and batches of up to 32. Per-problem records and `summary.json` retain the established evaluation schema; `vllm_timing.json` records engine startup and generation throughput. The worker uses a separate process and GPU assigned by PBS.

PBS job 61464 compared 16 MATH-500 and 16 AIME 2024 base-model examples against the completed Hugging Face FP32 evaluation. All 32 rewards agreed; 29 of 32 generated texts were exactly identical. Numerical implementation differences can change individual greedy trajectories, so the full base model is re-evaluated with vLLM for consistency rather than assuming exact equivalence. The comparison generated 22,714 tokens in 40.70 seconds, excluding 24.44 seconds of engine initialization; the original per-example generation times summed to 399.29 seconds. These are small-sample timing results.

The fresh batched base evaluation is PBS job 61465; its output is `runs/viability_fast2/evaluation/base`. Checkpoint evaluation and later training chains were requeued, preserving the four running stage-one training jobs. Their job manifest is `runs/viability_fast2_jobs.json`; final report job is 61542 and depends on the base evaluation as well as the four final checkpoint evaluations.
