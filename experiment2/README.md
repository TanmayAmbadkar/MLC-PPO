# Experiment 2: frozen DAPO critic validation

The first phase uses `BytedTsinghua-SIA/DAPO-Math-17k`, Qwen2.5-Math-1.5B-Instruct, and a Math-Verify reward matching the installed TRL `accuracy_reward` for parseable gold answers. `reward.py` is the intended shared reward entry point. Unparseable golds are rejected; a parser match does not prove that a gold label is mathematically correct.

The existing policy training entry point accepts `--reward-type trl_math` to call this same reward implementation. Its default `exact_match` is retained for the prior GSM8K pilot. No policy training is started by the validation scripts.

`pbs_experiment2_smoke.sh` collects 100 complete responses (up to 1,024 new tokens), saves full prompts and completions, compares the standalone reward with TRL, verifies the Qwen assistant suffix, tests same-length future-token perturbations, compares prefix-only features with full-forward features, and checks critic gradient isolation. The original 256-token exploratory smoke is in `runs/experiment2/smoke`; it had only two boxed responses and must not be used as a difficulty estimate. The longer run writes to `runs/experiment2/smoke_v2`.

`prepare.py` is a guarded dataset preparation stage: after the smoke report passes, it scans the official DAPO source, deduplicates normalized problems, excludes conflicting duplicate labels, filters unparseable answers, checks exact and Unicode/whitespace normalized matches against MATH-500 and AIME 2024/2025, and generates disjoint 1000/200/200 problem splits. These matching checks cannot detect semantic paraphrases. The script is not yet submitted as a job.

`collect.py` collects and saves prefix features, original trajectories, token IDs, and all independent continuation text. `analyze.py` fits the constant baseline, final-layer head and ensemble, and multi-layer heads for three seeds; it also compares mean, minimum and learned-gate aggregation. The gate is fit on one half of validation problems while the other half is used for early stopping. Difficulty-specific results use independently sampled 0/8, 1–7/8 and 8/8 prompt groups. `difficulty.py` independently samples eight full responses per problem, and `gradient_variance.py` computes restricted-policy score gradients using cached incremental forwards, checking them against saved generation log probabilities. `resource_benchmark.py` compares frozen-actor critic steps with shared heads and a separate full transformer critic. The resource smoke is not a full PPO memory benchmark.

The frozen-study gate takes the three head predictions as input, as in Experiment 1. The PPO gate reads layer features directly, so these are different gate parameterizations.

The requested split implies 105,600 state continuations (48,000 train, 19,200 validation, 38,400 test), before difficulty samples and initial trajectories. The gradient score and state collection smoke checks passed; the full collection is split across four resumable single-GPU PBS jobs. A dependent fitting job checks the exact problem and state counts, and the consolidated report waits for both fitting and the held-out checkpoint evaluation. The PPO code has separately passed sampler-ratio and one-update smoke checks. No PPO or GRPO updates are run by this frozen-policy experiment.
